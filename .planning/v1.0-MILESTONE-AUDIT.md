## 4. Cross-Phase Integration & E2E Flows

### Verified End-to-End User Flows

1. **Local Media Ingestion (Images & Videos):**
   - User drops PNG/JPG/WebP/GIF/MP4/WebM into `Dropzone.tsx` or rail file picker.
   - Media loads into `useStudioStore.loadMediaFile()`; dimensions and natural aspect ratio are calculated and bound to `CenterStage.tsx`.
   - Flow: **Complete & Verified**

2. **Live Webcam Real-Time Processing:**
   - User activates webcam from `LeftRail.tsx`.
   - `getUserMedia` attaches stream to persistent video element; `Pipeline.ts` binds `VideoTexture` to Three.js shader engine at 60 FPS.
   - Flow: **Complete & Verified**

3. **Real-Time 4-Stage Retro Shader Transformation:**
   - Stage 1 (Pre-Tone) -> Stage 2 (Primary Retro Shader) -> Stage 3 (Color Grading) -> Stage 4 (CRT/VHS Post-FX).
   - Sliders in `ToneControls.tsx` and `EffectInspector.tsx` update reactive uniforms in real time.
   - Automatic WebGL2 fallback activates if `navigator.gpu` fails.
   - Flow: **Complete & Verified**

4. **Instant Client-Side Multi-Format Export:**
   - User triggers export in `ExportDrawer.tsx`.
   - Instant raster snapshot (PNG/JPEG) via offscreen buffer.
   - Instant Rec. 601 luminance ASCII text file (`.txt`).
   - Instant standalone vector SVG (monochrome or TrueColor `<tspan>`).
   - In-browser quick social clip recording (WebM / GIF) with real-time percentage progress.
   - Flow: **Complete & Verified**

5. **High-Resolution Server-Side Video & GIF Export:**
   - User opens `ServerExportModal.tsx`. Client pings `GET /api/health` with exponential backoff (pre-warming).
   - Turnstile bot token acquired.
   - Canvas backing buffer locked to 1080p/720p with DPI decoupling.
   - Persistent Web Audio graph taps source audio without browser errors.
   - Sliced canvas stream uploads in 1000ms chunks to `POST /api/export/{id}/chunk` with bounded backpressure.
   - Source audio uploaded to `POST /api/export/{id}/source-audio`.
   - `POST /api/export/{id}/finalize` triggers background transcoding (`-threads 1 -preset ultrafast` or two-pass GIF).
   - Modal displays live ASCII progress bar while polling `GET /api/export/{id}/status`.
   - Server issues single-use download token; user downloads output from `GET /api/export/{id}/download`.
   - Flow: **Complete & Verified**

6. **Git-Driven $0/Month Cloud Infrastructure:**
   - Web studio deploys to Cloudflare Pages via `wrangler.toml` + `web/public/_redirects`.
   - Backend deploys to Render via `render.yaml` with single-worker Python environment, FFmpeg, and health monitoring.
   - Neon PostgreSQL schema documented in `docs/database-schema.sql` ready for future persistence.
   - Flow: **Complete & Verified**

## 5. Technical Debt & Non-Blocking Observations

No critical blockers or broken flows exist. The following non-blocking architectural items are noted for future milestones:

1. **Phase 1 Facade Standalone Status:**
   - The 36-symbol public facade in `src/__init__.py` (and underlying modules `src/renderer.py`, `src/video.py`, `src/sync.py`, `src/timing.py`, `src/framesel.py`, `src/smoothing.py`, `src/adaptive.py`) functions as a complete headless CLI engine and benchmark suite.
   - Phase 3 did not import `src` because Architectural Decision D-01 shifted the studio rendering pipeline to client-side GPU WebGPU/TSL shaders, leaving the Python backend to specialize in lightweight FFmpeg chunk transcoding (`src/api/transcode.py`). This was an intentional optimization to preserve Render's 512MB RAM limit.
2. **Minor Utility Duplication:**
   - `src/api/transcode.py` invokes `ffprobe` via a local helper (`validate_assembled_media`) rather than importing the probing utilities in `src/sync.py`.
3. **Phase 1 Code Review Observations:**
   - 7 non-blocking code review items documented in `01-REVIEW-DISPOSITION.md` (WR-01..04, IN-01, IN-02, IN-04) remain documented technical debt for future CLI enhancements.
